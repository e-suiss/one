# Security

One is proprietary and only Suiss team members work on it. The source is public so anyone can review it.

## Reporting a vulnerability

Report privately through GitHub's private vulnerability reporting: open the repository's **Security** tab and choose **Report a vulnerability**. Never put a vulnerability in a public issue, a pull request, a commit message or a discussion.

Include what is affected, how to reproduce it and the impact you expect.

## Handling

- A leaked secret is revoked or rotated first, then removed from history; it stays compromised once it has been public.
- Fixes ship under their own heading in the changelog. When users need to do something, the product and the release notes say so in plain language.
- Confirmed vulnerabilities are published as GitHub security advisories once a fix has shipped.
